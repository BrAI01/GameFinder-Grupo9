## Modalidad de trabajo

El proyecto se desarrolla de forma incremental en un único repositorio de GitHub. Cada trabajo práctico incorpora una nueva estructura o técnica sin eliminar las funcionalidades de las etapas anteriores.

## Organización

- rama principal: `main`;
- repositorio público compartido;
- commits descriptivos por funcionalidad o corrección;
- documentación por etapa dentro de `docs/`;
- revisión del estado del repositorio antes de cada entrega.

## Etapas implementadas

- TP0: propuesta inicial;
- TP1: primera versión funcional;
- TP2: búsqueda secuencial y binaria;
- TP3: Árbol Binario de Búsqueda;
- TP4: árbol AVL;
- TP5: árbol general o n-ario;
- TP6: heap binaria y ranking Top-N.

## Criterio de integración

Cada nueva estructura se incorpora a GameFinder manteniendo una aplicación ejecutable desde `main.py`. Los experimentos o pruebas específicas se conservan en scripts separados para poder reproducir las comparaciones sin sobrecargar el menú principal.

## Control de cambios

Antes de cada entrega se verifica:

1. que `main.py` pueda ejecutarse;
2. que los archivos de la etapa estén presentes;
3. que la documentación corresponda al código actual;
4. que el README refleje el estado real del proyecto;
5. que las funcionalidades previas no se hayan eliminado accidentalmente.
